# `order_saga_orchestrator` — Tasks

> Ordered. Work top to bottom. Each task is small enough to verify on its own; the implementer ticks `[x]` as it goes and **stops at the first task it cannot complete honestly**. Tests are written **inside** the loop — a task that adds behaviour and the task that proves it are adjacent, never batched to the end.
>
> **Requirement ids.** Shared `R19` – `R29` ([`specs/shared/requirements.md`](../shared/requirements.md) §3, elaborated by the whole of [`specs/shared/saga.md`](../shared/saga.md)). Local `SO1` – `SO11` ([`requirements.md`](./requirements.md) §2). Design section numbers below refer to [`design.md`](./design.md).
>
> **Two standing obligations, and they are why this list is shaped the way it is.**
>
> 1. **Every task that adds or changes behaviour names its own guard.** Feature 15 took three review rounds for one reason: *fixes shipped without guards* — every defect across all three passes was correct code that nothing would notice being reverted. The question to ask of your own work is not *"does it work?"* but ***"what fails if I revert this?"*** Tasks marked **⚑ ARM** are not finished until the arming is done and recorded; they are not a closing paragraph, they are per-task acceptance.
> 2. **Every branch that emits — or deliberately suppresses — a domain fact is armed individually** (`design.md` §11.2), **with double force for the five branches that have no live caller**, because no Fulfillment or Billing responder exists until phases 9 and 10 and no integration harness can reach them by accident.
>
> **Arming protocol (CLAUDE.md, verbatim in effect).** Back up the file **by copy** — never `git checkout --`, which fails silently on an untracked file and leaves it armed. Introduce the violation. Run **the specific named test**. Confirm it FAILS and record the message **verbatim** in `progress/impl_order_saga_orchestrator.md`. Restore from the backup. **Force the rebuild** (`touch` the restored file, or `dotnet build --no-incremental`). Re-read the changed line to confirm the restore. Only then the confirming green run. An arming table produced without a forced rebuild proves nothing about the code on disk.
>
> **Hard boundaries for this feature.**
> - **No migration, and none may be written** (`design.md` §7). `saga_commands` and `saga_ignored_facts` already exist with every column and index this design needs. If a column seems missing, **stop and report** — do not add one.
> - **Nothing under `src/Orders/Domain/` changes.** If a step seems to need a new aggregate method, stop and report: that is a finding about feature 13.
> - **`specs/shared/` is read-only** except column 5 of `test-matrix.md` and the two derived count rows, at close-out only.
> - **`IdempotentConsumer` and `ProcessedEventLedger` are canonical and parity-guarded — do not edit either.**
> - **No new NuGet package.** If one seems necessary, stop and report.
