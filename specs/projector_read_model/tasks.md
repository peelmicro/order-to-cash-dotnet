## How to read this file

**`⚑ARM` marks a task that makes a countable claim** — a count, an identity, an ordering, or an absence. Every one of them must be **seen to fail** before it is ticked: introduce the violation, run the named test, confirm it FAILS, record the message **verbatim**, restore from a backup copy (never `git checkout --`), `touch` the restored file or `dotnet build --no-incremental`, and only then run the confirming green. A tick on a `⚑ARM` task without a recorded failure message in `progress/impl_projector_read_model.md` is not evidence the assertion exists.

**Two mutation families, not one.** *Delete the emission* and *corrupt the payload* find different defects. A guard that counts a row and never opens it passed feature 17 perfectly and shipped a payload defect. Where a task says "carrying X", the arming must include corrupting X. Where the field is one the test does not control — an id, a clock, a generated reference — inject the source or bracket the value; `Assert.NotEqual` proves non-collision and can never prove provenance.

**Three standing rules bind every task here:**

1. **Synchronise only on terminal or monotonic evidence** (design §11). This service is a race by construction; never poll for an intermediate status a correct system passes through, and never `sleep`.
2. **`N10`.** An assertion that an absent side effect did not happen proves **nothing** about whether it was attempted. Wherever a task says "no duplicate entry" or "no signal", it also requires observing the *attempt* — the `null` from `FindOneAndUpdateAsync`, or a counter on the post-apply callback — not only the document's final contents.
3. **Tick as you go.** #7's implementation of this exact feature was **rejected at review** with `tasks.md` at **0 of 63 ticked** and zero code defects found (`order-to-cash-nestjs/progress/review_projector_read_model.md` N1). Tick each box when it is done; reword any box whose delivered shape differs from the plan, on the box, rather than ticking over a description that is no longer true.

**Do not edit** `specs/shared/` (other than this feature's own Status cells in `test-matrix.md` §7 — N4), `src/Orders`, `tests/Orders.*`, `src/Seed`, `tests/Seed.*`, `src/Notifications`, `tests/Notifications.*`, `src/Gateway`, `src/Cqrs`, `src/Contracts`, `src/SharedKernel`, `apps/web`, or `feature_list.json` beyond the transition N8 asks for.
