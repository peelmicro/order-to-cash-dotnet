# `outbox_and_idempotency` — Tasks

> Ordered. Each task is small enough to verify on its own. The implementer ticks `[x]` as it goes and stops at the first task it cannot complete honestly. Tests are written **inside** the loop — a task that adds behaviour and the task that proves it are adjacent, never batched to the end.
>
> **Order of groups: A → B → C → D → E → F → G → H → I.** A comes first because every later group compiles against the new ports and the new envelope guard; B (the fixture's isolation level) comes before any concurrency test, because a concurrency test run against a database configured differently from the deployed one proves nothing about the deployed one.
>
> Requirement ids: shared `R11` – `R18` ([`specs/shared/requirements.md`](../shared/requirements.md) §2; **`R16` is deferred to feature 27**, argued in [`requirements.md`](./requirements.md) §1.2 and **pending ratification at the gate** — if the gate rules otherwise, stop and re-spec rather than improvising a consumer). Local `OI1` – `OI16` ([`requirements.md`](./requirements.md) §2). Design: [`design.md`](./design.md).
>
> **No migration is written by this feature and none may be** (`design.md` §3). Every column and index the relay needs already exists and is already asserted by feature 9/10/11 tests. If a column seems missing, stop and raise it — do not add one.
>
> **Do not edit `specs/shared/` except column 5 of `test-matrix.md`** (rows `R11` – `R15`, `R17`, `R18`, plus the derived counts). Do not edit `specs/orders_aggregate/` at all.
