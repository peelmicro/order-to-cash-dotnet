## How to read this file

**`⚑ARM` marks a task that makes a countable claim** — a count, an identity, an ordering, or an absence. Every one must be **seen to fail** before it is ticked: introduce the violation, run the named test, confirm it FAILS, record the message **verbatim** in `progress/impl_observability_reliability.md`, restore **from a backup copy you took** (never `git checkout --`), `touch` the restored file or `dotnet build --no-incremental`, and only then run the confirming green. **A tick is not evidence the assertion exists.**

**Three mutation families, not one.** *Deletion* (remove the emission), *corruption* (change a field the test supplied), *substitution* (swap one real identifier for another real one from the same family). This feature touches four sibling families and every one of them is a substitution target: the `otc-*` Kafka client ids, the `*.v1` event types, the fifteen NATS subject constants, the topic names, and the new `*_HEALTH_PORT` variables. **A swap that fails is not evidence until the failure message names what you intended to break** — if the sibling is unset and the read falls back to a default, the test failed for the wrong reason.

**A corruption probe only bites on a field whose expected value the test supplied.** For ids, clocks and generated references, inject the source or bracket the value; `Assert.NotEqual` proves non-collision and can never prove provenance.

**Three standing rules bind every task here:**

1. **Pace every retry/readiness loop explicitly** (design §12 rule 2). The fast-failing error is what breaks an attempt-counted budget, and it is invisible while every failure happens to be a timeout.
2. **Synchronise on terminal or monotonic evidence.** Never a bare sleep; never an intermediate state a correct system passes through.
3. **Tick as you go**, and reword any box whose delivered shape differs from the plan **on the box**, rather than ticking over a description that is no longer true.

**Do not edit** `specs/shared/` — **with one exception**: this feature's own **Status cells** in `test-matrix.md`'s `R16`, `R29`, `R56`–`R60` and `R62` rows (column 5 is each assessment's own realisation record; every other byte of `specs/shared/` is `cmp`-checked against #7 by `init.sh` §5d). Do not edit `apps/web`, `infra/`, `n8n/`, or `feature_list.json` beyond the transition N6 asks for.

**Scope by service.** This feature legitimately touches all six services plus `Contracts`. What it must **not** touch: `src/SharedKernel`, `src/Cqrs`, `src/Seed`, `infra/`, and any file under `src/Fulfillment`/`src/Billing` other than the ones tasks A1, A3 and A4 name.
